# Performance Optimization Guide

This document outlines the performance strategies implemented in EpochBridge to ensure a fast and responsive user experience.

## Caching Strategy

The most computationally expensive part of the application is date conversion. To mitigate this, we use Laravel's caching system extensively.

### Conversion Caching

In `app/Services/DateTimeConverterService.php`, every conversion result is cached.

-   **Cache Key**: A unique key is generated by creating an MD5 hash of the input date string and input type (`'conversion_fast_'.md5($dateString.$inputType)`).
-   **Cache Duration**: Results are cached for 3600 seconds (1 hour). This is a good balance, as date conversions are deterministic and will not change.
-   **Two-Tier Caching**: Caching is split between "fast" and "additional" calendars to optimize the initial load. The primary, most common calendars are cached in one block, and the more complex/ancient calendars are cached in a separate block.

## Lazy Loading Calendars

The initial page load should be as fast as possible. Displaying all 15+ calendar conversions at once can be slow. We use a lazy-loading strategy for less common calendars.

-   **Initial Load**: The `DateTimeConverterService::convert()` method only computes and returns the "fast" calendars (Gregorian, Jalali, Unix, and a few others).
-   **Intersection Observer**: In `calendar-results-grid.blade.php`, we use Alpine.js's `x-intersect` directive. When the loading skeleton section scrolls into the viewport, it dispatches a `load-additional-calendars` event to Livewire.
    ```blade
    <div x-intersect.once="$wire.dispatch('load-additional-calendars')">
        ... loading skeletons ...
    </div>
    ```
-   **Loading Additional Data**: The `landing` component listens for this event and calls `DateTimeConverterService::convertAdditional()`, which computes and caches the remaining calendars.

## Frontend Optimizations

-   **Debouncing Input**: To prevent firing too many conversion requests while the user is typing, `wire:model.live` is combined with `.debounce.300ms` for text-based inputs.
-   **Loading States**: All actions that trigger a server roundtrip (e.g., "Convert Date") have `wire:loading` states to provide immediate feedback to the user and prevent double-clicks.
-   **Vite Build**: For production, `npm run build` compiles and minifies all assets, and Tailwind CSS purges all unused styles for a minimal CSS footprint.
